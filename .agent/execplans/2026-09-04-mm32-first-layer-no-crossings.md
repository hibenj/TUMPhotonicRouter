## Surprises & Discoveries

- (10:27, probe cells along the hypothetical crossing-free path, probe report now also printed on search success `978619f`) ROOT CAUSE: the static target stubs of ALL MZI ports form horizontal bars at x=679..689 every 50 rows ((679..686,289) and (683,240) are static and unopened for n_34); between two bars the stub column is a POCKET reachable only from the west. n_33 (lower target, routed FIRST because o3 precedes o2 in the net order) takes its shortest path: diagonal to (677,279), then a vertical at x=677 -- hugging the stub column -- down to 143. That vertical plus its diagonal corner seal n_34's pocket (rows 194..288) from the west; the bar at 289 seals it from above. n_34 can only enter by crossing n_33 (and must cross its diagonal first to get underneath). The search reached (677,289) (acc=6) and (683,280) (acc=10) -- but (683,280) is only reachable through the crossing. With the opposite order (upper output first) n_34 would take x=677 down to 193 and n_33 would pass 2 cells further west down to 143: crossing-free. So: ORDERING + greedy shortest path, not spacing halos, congestion or the cost model. The same pattern for n_58/n_59.

## Decision Log

- (2026-09-04 10:30, open for the owner) How to order nets so the greedy shortest path of an earlier net does not seal a sibling's target pocket. Candidates: (a) within a fan (same source instance, ordered targets), route the net whose target is on the INSIDE of the fan first -- for the yb_4 -> mzi layer that is the upper output for the lower half... more precisely: the net whose shortest path hugs the shared stub column must be the one that turns off first (target closer to the shared straight); a general rule: order siblings so that the target that is passed LAST along the shared corridor is routed first ("outermost target first" = the net that must travel furthest along the stub column is routed last? -- needs the geometric criterion to be written down and tested on both fan directions); (b) LiDAR-style: order by target position monotonically per layer (e.g., by target y descending/ascending) -- cheap, but the correct direction depends on whether the fan converges or diverges; (c) a post-pass: detect double crossings of the same pair (A x B twice) and reroute the pair in swapped order -- fully general, no geometry assumption, catches exactly the observed pattern.
